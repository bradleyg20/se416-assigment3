## Part 1

| # | Problem in original code                                 | Refactoring technique                                                                                                                                | Benefit                                                         |
| - | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1 | **Monolithic method doing ≥ 6 things**                   | **Extract Method** (`fetchSheet`, `decideName`, `copyPackageRelations`, `copyExternalLinks`, `copySheetXml`, `stripUnsupportedParts`, `copyDrawing`) | Single-responsibility helpers are short, testable and readable. |
| 2 | **Deep nesting of conditionals**                         | **Guard clauses** (early validation/return)                                                                                                          | Reduces indentation and cognitive load.                         |
| 3 | **Low cohesion / high coupling**                         | **Hide helpers** (`private`) & pass only what each needs                                                                                             | Limits class surface; each helper manipulates one concept only. |
| 4 | **Ambiguous names**                                      | **Rename** (`src`, `dst`, `copyExternalLinks`, etc.)                                                                                                 | Communicates intent instantly; no need to read the body first.  |
| 5 | **Duplicated try/with-resources blocks**                 | **Introduce parameter object** (`copySheetXml`)                                                                                                      | Centralises stream handling & uniform exception translation.    |
| 6 | **Mixed policy & mechanism (logging inside loop, etc.)** | **Separate concerns** (`stripUnsupportedParts`)                                                                                                      | Logging and corrective XML edits live in a dedicated helper.    |
| 7 | **Unchecked runtime errors bubbling inconsistently**     | **Consistent exception translation** (`POIXMLException` with causal chain)                                                                           | Client code receives one predictable, domain-specific error.    |
| 8 | **Hidden side-effect (drawing reset)**                   | **Make side-effect explicit** (`copyDrawing` performs all drawing logic)                                                                             | Readers immediately see where drawings are handled.             |
